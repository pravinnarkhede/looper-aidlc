# Command: /bridge-jira-sync

Reads AIDLC user story output for the active feature and creates a Jira Epic with child Stories using the Atlassian MCP.

---

## Step 1 — Identify the active feature

Scan `aidlc-docs\` for feature subfolders (exclude `reverse-engineering\`).

If more than one feature exists, present a numbered picker:

```
Which feature do you want to sync to Jira?

  [1] {feature-name-1}
  [2] {feature-name-2}

Enter a number:
```

If only one feature exists, use it automatically and confirm:
```
Active feature: {feature-name}
```

---

## Step 2 — Locate and validate AIDLC story files

Check that both files exist:
- `aidlc-docs\{feature-name}\inception\user-stories\stories.md`
- `aidlc-docs\{feature-name}\inception\user-stories\personas.md`

If either file is missing, stop and tell the user:
```
❌ User stories not found for feature: {feature-name}

Expected:
  aidlc-docs\{feature-name}\inception\user-stories\stories.md
  aidlc-docs\{feature-name}\inception\user-stories\personas.md

Run the AIDLC User Stories stage first, then re-run /bridge-jira-sync.
```

---

## Step 3 — Ask for Jira details

Prompt the user for the required Jira parameters:

```
Jira sync for feature: {feature-name}

Please provide:
  1. Jira project key  (e.g. GCA, CCD, GOLF)
  2. Epic title        (default: {feature-name in Title Case})
  3. Labels to apply  (optional, comma-separated, e.g. aidlc,membership)
  4. Assignee         (optional — Jira account email or leave blank)

Reply in this format:
  project: GCA
  epic: Membership Class Sale
  labels: aidlc, membership-class-sale
  assignee: developer@company.com
```

Wait for the user to reply. Parse the key-value pairs from their response.

---

## Step 4 — Read and parse the story files

Read `stories.md` in full. Parse it into a list of user stories. Each story has:
- **Title**: the "As a [persona], I want [goal]" line (used as the Jira Story summary)
- **Description**: the full story block including "so that" clause
- **Acceptance criteria**: the bullet list under "Acceptance Criteria" for that story

Also read `personas.md` — use its content as additional context in the Epic description.

---

## Step 5 — Authenticate with Atlassian MCP (if needed)

Use the Atlassian MCP tool `atlassianUserInfo` to check if the user is already authenticated.

If not authenticated, the MCP will prompt the user to log in via browser. Wait for authentication to complete before proceeding.

Confirm connection:
```
✅ Atlassian connected as: {user display name} ({email})
```

---

## Step 6 — Confirm before creating

Present a summary and ask for confirmation before creating anything in Jira:

```
Ready to create in Jira project {PROJECT}:

  Epic:  "{epic title}"
  Stories ({N} total):
    1. As a {persona}, I want {goal}...
    2. As a {persona}, I want {goal}...
    ...

  Labels:   {labels}
  Assignee: {assignee or "unassigned"}

Create these issues? (yes / cancel)
```

Wait for explicit confirmation. If the user says cancel or no, stop without creating anything.

---

## Step 7 — Create the Epic

Using the Atlassian MCP `createJiraIssue` tool, create the Epic:

- **Project**: the project key from Step 3
- **Issue type**: Epic
- **Summary**: the epic title from Step 3
- **Description**: 
  ```
  Feature: {feature-name}
  Generated by AIDLC Inception phase.

  ## Personas
  {content of personas.md}

  ## Source
  AIDLC docs: aidlc-docs\{feature-name}\inception\user-stories\
  ```
- **Labels**: apply all labels from Step 3

Store the returned Epic issue key (e.g. `GCA-45`).

---

## Step 8 — Create Stories as children of the Epic

For each user story parsed in Step 4, use `createJiraIssue`:

- **Project**: same project key
- **Issue type**: Story
- **Summary**: the "As a [persona], I want [goal]" line
- **Description**:
  ```
  {full story text including "so that" clause}

  ## Acceptance Criteria
  {acceptance criteria bullet list}
  ```
- **Labels**: same labels as the epic
- **Assignee**: if provided in Step 3
- **Epic link**: link to the epic created in Step 7

After each story is created, output a one-line confirmation:
```
  ✅ GCA-46  As a member, I want to purchase a class pass...
  ✅ GCA-47  As a staff member, I want to view class pass sales...
  ...
```

---

## Step 9 — Update bridge-docs\bridge-config.md

Find the feature block in `bridge-docs\bridge-config.md` and add a Jira row:

```
| **Jira Epic** | [{epic-key}] — {epic title} |
| **Jira Stories** | {story-key-1}, {story-key-2}, ... |
| **Synced** | {today's date} |
```

---

## Step 10 — Present completion summary

```
✅ Jira sync complete — {feature-name}

  Epic:    {EPIC-KEY} — {epic title}
  Stories: {N} created
    {STORY-KEY-1}  As a member, I want...
    {STORY-KEY-2}  As a staff member, I want...
    ...

  bridge-docs\bridge-config.md updated.

Next: run /looper-plan {EPIC-KEY} to start Construction and link the RePIT to this epic.
```

---

## Error handling

| Problem | What to do |
|---------|-----------|
| Atlassian auth fails | Tell user to check MCP connection in Claude settings and retry |
| Project key not found | Ask user to verify the project key and retry Step 3 |
| Epic creation fails | Report the MCP error, do not proceed to story creation |
| A story creation fails | Report the failure, continue with remaining stories, list failures in the summary |
| `stories.md` has no parseable stories | Stop and ask user to check the file format |
